## Phase Three — retailer inventory foundation
Read-only live schema inspection found `inventory_items.image_urls` and `try_on_image_url`, not the old client `images` and `tryOn_image` names; no `variants` column exists; `location_id` is a nullable UUID. The previous form always sent unsupported columns and an empty UUID, hid save errors and optimistically closed before confirmation. This change maps the real fields, omits unsupported variant payloads, blocks nonempty variant stock instead of silently losing it, validates numeric fields and location, preserves zero thresholds, and closes only after successful write. SKU duplicate checks are advisory against loaded local inventory and scoped to location. RLS policy definitions require `manage_inventory` for insert/update/delete; this inspection is not a live permission test.

CSV preview uses a bounded, local parser with explicit headers, quote handling, row validation, and duplicate checks. It does not write records, upload files or publish offers. The prior sync endpoint counted local rows without publishing canonical products; UI now says Refresh Catalog rather than reporting a false sync. Online offers remain separate and read-only. No production data or database schema changes.

Remaining: actual database insert/update acceptance in a safe test context; server-enforced SKU uniqueness, location ownership, variant links, import transaction/idempotency, authorized bulk commit and canonical publication. Do not represent this preview as bulk import completion. Keep retailer image rights and live payment gates intact.
